## Design Context

### Users

The primary audience is developers evaluating or installing `swagger-doc-skill` for Codex. They need to understand the value quickly, inspect a real API extraction result, and copy an installation prompt or open the repository.

### Brand Personality

Precise, candid, and engineer-to-engineer. The experience should feel credible, practical, and restrained.

### Aesthetic Direction

Use a light technical-editorial direction with warm neutral surfaces, dark ink typography, restrained Swagger green accents, and real API output as the primary visual. Avoid generic AI gradients, neon dark mode, glass effects, decorative blobs, and repetitive card grids. Support responsive layouts, visible focus states, and reduced motion.

### Design Principles

1. Lead with a real product state, not abstract decoration.
2. Keep the install action obvious and easy to copy.
3. Make every capability claim traceable to the repository.
4. Create hierarchy with typography, alignment, and spacing before adding containers.
5. Preserve critical actions and readable code examples on every viewport.
